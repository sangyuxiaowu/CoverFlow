CoverFlow - 专业 SVG 文章封面设计器
=====================================

面向多平台文章封面与系列配图的设计工具，支持 Web、PWA 和桌面端。以项目组织多个独立页面，结合 SVG 资源库、图层编辑、背景设计与 AI 助手，完成从素材整理、版式制作到图片、SVG 和演示稿导出的工作流程，适合日常内容运营与设计协作。

![软件界面](./doc/i1.png)

使用方式
--------

- 在线使用：https://sangyuxiaowu.github.io/CoverFlow/
- 安装为桌面/应用：在浏览器菜单中选择“安装应用”（PWA）
- 前往 [Releases](https://github.com/sangyuxiaowu/CoverFlow/releases) 下载桌面版安装包：
	- 打开最新版本（Latest）
	- 选择与你的系统匹配的安装包（Windows/macOS/Linux）

核心功能
--------

### 项目与页面

- 一个项目包含 1-99 个页面，每页独立保存尺寸、背景和图层，可用于同一文章的多平台封面、系列配图或演示稿
- 新建项目从一页开始；左侧页面面板支持添加、重命名、切换、复制、删除和拖动排序。未命名页面以 P01-P99 显示，编号随排序变化；项目至少保留一页
- 添加页面沿用当前页尺寸和背景，也可指定尺寸；复制页面保留完整内容，副本可独立编辑。图层编辑、背景设置和剪贴板添加均作用于当前页
- 页面缩略图便于浏览与切换；项目库以第一页作为封面，多页项目显示页数徽标。打开或重新导入项目时从第一页开始
- 撤销 / 重做记录项目内容变化，不单独记录切页和图层选区；恢复内容时优先保留仍存在的当前页
- 项目库支持浏览、重命名、复制和删除；复制项目包含所有页面

### 保存与项目文件

- 浏览器存储使用 IndexedDB 保存项目；LocalStorage 仅保存语言、视图偏好和部分预设等设置
- 浏览器文件模式通过 File System Access API 读写已授权目录，需支持该 API 的浏览器及 HTTPS 或 localhost；Tauri 桌面版通过原生文件接口读写项目
- 项目支持自动保存和手动保存，可导入 / 导出 `.cfj` 后缀的 JSON 文件，用于继续编辑、备份和分享；文件包含所有页面的尺寸、背景、图层及内嵌资源，不保存当前活动页和图层选区
- 旧单页项目可直接打开，并作为项目的第一页继续编辑；后续保存使用多页结构，读取本身不会覆盖旧文件

### 画布系统

- 多比例画布：内置微信文章封面比例（2.35:1、1:1），同时可自定义
- 画布控制：缩放、滚动平移、重置缩放
- 各页尺寸可独立调整，同一项目可同时制作不同平台比例的封面
- 预览：从当前页开始只读的全屏查看，类似 PPT 播放
- 预览图片按页面内容复用，最多保留 100 项最近使用的缓存；内容变化生成新键，复制或改名不重复生成。缓存为长边不超过 2048px 的 WebP，不影响成品导出分辨率
- 缓存优先生成当前页及后续邻页，其余页面在空闲时逐步补齐；内容哈希和图片编码使用 Worker，DOM 截图在主线程空闲时串行执行。未缓存或不支持 Worker 时保持实时预览，关闭预览会取消后台任务

### SVG / PNG 资源管理

- 分类资源库：内置基础图形、装饰元素、可加载用户自定义 SVG / PNG 资源文件夹
- 搜索与过滤：按名称关键词筛选

### 装饰库

- 内置装饰库：提供一批可直接添加到画布的预置装饰
- 自定义装饰：支持 CSS 声明或静态 HTML（含内联样式和作用域化 `<style>`），自动识别类型，也可手动切换
- 装饰检查器：编辑源码、HTML 节点文本与内联样式；自动识别 CSS 变量并生成对应控件，每个颜色变量可通过独立色板调整
- 变量拾色器：支持 HEX（含透明度）、RGB/RGBA、HSL/HSLA、OKLCH 与 CSS 命名颜色；提供透明度滑块、通道输入和格式切换。色板交互使用 sRGB，OKLCH 可通过数值编辑；屏幕取色需浏览器支持 EyeDropper API，不支持时按钮禁用
- 装饰模板：可将当前画布中的多个图层保存为装饰模板，便于复用整套角标、边框、排版组合

### 图标库

- 集成 Font Awesome 图标库（需手动加载数据）
- 启用方式：从 Font Awesome 下载 `icon-families.json` 与 `categories.yml`，在图标库面板上传后即可使用
- 支持搜索与分类浏览，一键添加到画布生成图层

### 图层编辑系统

- 图层面板：列表展示当前页图层，页面之间独立编辑
- 图层操作：
	- 位置调整（XY 拖拽 / 精确数值输入）
	- 缩放（等比 / 非等比，拖拽 / 数值控制）
	- 旋转（自由旋转 / 15 度步进）
	- 顺序调整（拖拽排序）
	- 显示 / 隐藏 / 锁定
- 装饰图层：支持颜色联动、自定义宽高与样式内容编辑
- 文本增强：文字渐变，保留输入的换行、空行与空格；字距按像素设置，行距按字号倍数设置（默认 1.1，范围 0.5-5，支持输入和拖动调整）。竖排时行距控制列间距；改变行距不会自动扩大文字框，内容放不下时需调整文字框尺寸
- 历史操作：撤销 / 重做

### 背景系统

- 纯色 / 线性渐变 / 图片 / 自定义 CSS 背景，CSS 支持多层渐变、背景纹理和自定义变量
- 叠加纹理：条纹、网格、波点
- 背景图片：上传或链接
- 预置背景：常用渐变方案与自定义预设

自定义背景填写 CSS 声明（不含选择器），仅支持 `background` 相关属性和 CSS 变量。装饰 HTML 最多 24000 字符、300 个元素，CSS 最多 6000 字符。两者都不执行脚本，不支持外部资源、CSS at-rule、动画、固定定位和视口单位；使用百分比或像素适配画布。HTML 图片仅接受嵌入的 PNG/JPEG/WebP/GIF，普通图片资源仍使用图片图层。HTML 源码保存在项目与装饰库中，清洗和样式作用域只在渲染时生成。

### 导出与分享

编辑页支持按“本页 / 多选 / 全部”导出，默认当前页。多选和全部范围提供页面缩略图、名称、尺寸、已选数量，以及全选和反选；也可切换到大图预览，按项目顺序检查已选页面。未选择页面时不能导出。

| 格式 | 输出与设置 | 注意事项 |
| --- | --- | --- |
| PNG / JPEG / WebP | 按各页画布尺寸与像素倍率渲染，支持压缩质量设置 | 一页输出图片，两页及以上按项目页面顺序打包 ZIP |
| SVG | 按各页画布尺寸输出，一页为 SVG，多页为 ZIP | 文字和 CSS/HTML 装饰使用 `foreignObject`，需查看器支持；像素倍率和压缩设置不适用 |
| PPTX | 每个所选页面作为一张完整 PNG 放入演示稿，像素倍率控制清晰度 | 图片型演示稿，不含原生可编辑文字或图形；整份文件采用确认导出时当前页的比例，其他尺寸页面等比留白、不拉伸；压缩选项不适用 |

导出使用完整页面重新渲染，不以列表缩略图代替成品。大图预览会同步当前编辑页，但不改变导出范围和勾选结果；非 PPT 格式显示当页输出尺寸与预计大小，该估算不代表整个 ZIP 或 PPTX 的体积。

“本页”范围还可复制当前页图片或 Base64；项目库提供 PNG 快速导出。需要保留可编辑内容时，使用 `.cfj` 项目文件而非成品图片或 PPTX。

### AI 助手

- 全局 AI 入口，项目库和编辑页均可使用，通过 OpenAI 兼容接口与工具调用操作项目
- 项目搜索（分页查询存储）、新建、打开、重命名、复制、确认删除和保存
- 页面管理：读取页面列表、添加、切换、复制和确认删除；可逐页制作内容，图层编辑、画布预览、生图和抠图均针对当前页。页面重命名、排序及成品导出由人工界面完成，AI 不提供这些工具
- 创建文字、SVG、图片和 CSS/HTML 装饰图层；批量修改内容、位置、大小、旋转、透明度、文字渐变/阴影、显隐和锁定
- 图层复制、删除、组合/拆组、置顶/置底、画布对齐和等间距分布；调整画布和背景
- 修改进入编辑历史，可使用现有撤销/重做；工具记录可展开查看结果，支持停止执行
- 可拖动、缩放、最小化和最大化的浮窗，记忆位置与尺寸；聊天中按接入点分组切换模型
- 多个接入点和各自的模型列表，独立配置上下文容量、输出上限、思考参数和视觉输入能力
- 视觉模型支持粘贴或上传图片、预览当前画布；图像以 WebP 压缩且长边不超过 600px
- 会话独立保存，支持新建、切换、重命名和确认删除；刷新恢复当前会话及正文、思考、工具记录和图片附件
- 生图：独立配置 Kolors、Agnes 或 GPT-Image 兼容模型，支持文生图、单图参考和按模型能力批量生成，结果自动加入当前画布并保留原始 PNG/JPEG/WebP 字节
- 素材工具：搜索已授权素材文件夹并按精确 ID 放置 SVG/PNG；不搜索内置素材，不弹出授权窗口
- 纯文本 SKILL：按需配置设计规则，模型先读取名称和简介，调用工具后才获取正文；默认列表为空，不执行脚本
- 本地抠图：图片图层和 AI 均可调用 U2NetP、BiRefNet Lite 512、MODNet，图片在本地 Worker 中处理；模型与运行时说明见 [本地抠图](doc/background-removal.md)

#### 模型接入与用量

在 AI 浮窗的模型设置中维护多个接入点，填写 API 基础地址、模型列表和 API Key，支持 OpenAI、DeepSeek、Ollama 预设与自定义 Responses 兼容服务。请求使用官方 OpenAI SDK 的 Responses API，模型必须支持函数工具调用。基础地址示例：OpenAI 为 `https://api.openai.com/v1`，DeepSeek 为 `https://api.deepseek.com`，Ollama 为 `http://localhost:11434/v1`。按模型配置支持的思考档位，通过 `reasoning.effort` 统一控制，无需设置思考协议。

每个模型可配置上下文窗口 Token 与最大输出 Token；前者用于客户端预算和占用比例，不会改变服务端容量。Ollama 的实际上下文还需在服务端配置 `num_ctx`。输入区展示上下文估算、占用百分比和预留输出预算，展开后可查看上次输入实测、本次操作及会话累计用量、输入/输出、缓存命中、思考 Token 和请求次数。缓存与思考计数是输入/输出的子集，不重复累加；工具循环的每次请求均计入消耗。下一次上下文估算使用 UTF-8 字节启发式，并以同模型的最近实测输入校准，不是服务端精确计数。中断或未返回 usage 的请求标记为统计不完整，不伪造为零。

#### 会话存储与密钥

浏览器模式下，模型、连接、会话、图片二进制和 AI 界面状态分别保存在 IndexedDB。文件模式下，存储目录（Tauri 为当前项目旁）的 `chat/config.json` 保存配置与加密 Key，`chat/ui.json` 保存窗口与当前会话状态，`chat/sessions/<会话ID>.json` 保存会话记录，`chat/images/<会话ID>/` 保存独立 PNG/JPEG/WebP 图片；删除会话会同时删除其图片。加入画布的图片会内嵌到项目，不依赖会话继续存在。切换存储模式不会自动混合两边记录。

API Key 参考 SangDocCraft 使用 AES-GCM 256 位加密，配合随机 IV 和保存在本机 IndexedDB 中、不可导出的 CryptoKey，刷新后自动恢复。首次使用需在“其他设置”创建或导入主密钥；创建或换钥时提供一次口令加密备份机会，导入同一备份后可跨浏览器/设备解密相应配置。仅复制 `chat` 文件夹不能备份主密钥。正常换钥会保留并重新加密当前可恢复的 API Key；解密失败时可导入备份，或明确确认重置并重新填写。浏览器配置和密文同事务提交，文件配置以单文件提交。清除站点数据会删除本机主密钥，无备份时无法恢复旧密文；该方案不防御同源恶意脚本或浏览器环境被攻破。浏览器直连端点，服务需允许 CORS；线上 HTTPS 页面不能访问普通 HTTP 服务。

#### 数据与操作边界

发送消息意味着允许将提示词及工具读取的项目标题、当前页画布、图层内容和页面元数据发送到配置的服务商。视觉模型启用后，用户主动附加的图片和 AI 请求的当前页预览会以压缩 WebP 发送；不会上传本地文件路径。切换至非视觉模型时，待发图片暂存于输入区，历史图片仅在出站请求中替换为文字标记，不删除原图；待发暂存不跨刷新保存。生图另行调用用户配置的图像服务，可能产生费用，客户端停止不保证服务商免计费。

删除项目或页面需单独确认；AI 执行期间暂停手动编辑。异步生图、素材放置和抠图在应用结果前校验项目及当前页，避免写入错误页面；已生成图片仍保留在会话，不因放置失败自动重新生成。停止不会撤销已完成的操作。

架构及扩展方式见 [AI 模块说明](doc/ai-architecture.md)。

### 预设与模板

- 背景预设：保存和复用常用背景方案
- 装饰元素：保存常用单个装饰，构建个人装饰库
- 装饰模板：保存当前画布中的多图层组合，适合沉淀常用版式组件

### 剪贴板与快速添加

- 粘贴 JSON 内容：应用到当前页，不修改项目 ID 和标题；粘贴完整多页项目 JSON 时先兼容读取，再取第一页内容应用到当前页，不导入全部页面
- 粘贴文本：快速生成文本图层
- 粘贴 SVG 代码 / SVG 文件：快速生成 SVG 图层
- 粘贴图片文件：快速生成图片图层

快捷键
------

- Delete / Backspace：删除选中图层
- Arrow Keys：1px 移动
- Shift + Arrow：10px 移动
- Ctrl + J：克隆选中图层
- Ctrl + G：组合图层
- Ctrl + 上下：调整图层层级
- Ctrl + 左右：调整旋转角度
- Enter：编辑文本图层，也可以使用双击
- Ctrl + Z：撤销
- Ctrl + Y：重做
- Ctrl + S：保存项目

本地开发
--------

前置要求：安装 Bun；Node.js 需为 20.19+（20.x）或 22.12+，以满足 Vite 7 的运行要求。

```bash
bun install
bun run dev
```

构建与预览：

```bash
bun run build
bun run preview
```

测试与类型检查：

```bash
bun run test
bun run typecheck
```

目录结构
--------

```
.
├─ src/                # 前端应用源码，测试与对应模块放在一起
│  ├─ assets/          # 随前端打包的图片与 Logo
│  ├─ components/      # UI 组件与面板
│  ├─ features/        # AI、背景移除等独立功能模块
│  ├─ hooks/           # 业务 Hooks
│  ├─ views/           # 落地页、项目浏览区与预览条目
│  ├─ storage/         # 存储适配器
│  ├─ utils/           # 工具函数
│  ├─ App.tsx          # 顶层视图切换与编辑状态
│  ├─ index.tsx        # React 挂载入口
│  ├─ index.css        # 全局样式
│  ├─ constants.ts     # 常量与默认配置
│  ├─ types.ts         # 类型定义
│  ├─ translations.ts  # 文案与多语言
│  └─ vite-env.d.ts    # Vite 与浏览器 API 类型声明
├─ src-tauri/          # Tauri 原生端
├─ scripts/            # 构建/同步脚本
├─ doc/                # 文档与素材
├─ public/             # PWA 资源与静态文件
├─ index.html          # Vite HTML 入口
├─ vite.config.ts      # 开发与打包配置
└─ tsconfig.json       # TypeScript 配置
```

应用源码统一位于 `src/`，`@/` 别名指向该目录。`public/` 中保留按 URL 直接访问的图标和模型文件；构建脚本、配置、文档与 Tauri 原生工程不放入前端源码目录。
