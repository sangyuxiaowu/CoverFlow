# 已知问题

## 大型 AI 会话仍包含完整项目撤回快照

**状态：运行时放大问题已缓解，存储体积优化待处理**

AI 每次用户提问保留完整项目快照以支持撤回。复制页面后隐藏的旧图仍属于项目内容，图片 Base64 因而会重复出现在多个快照中；生成图片文件的总大小不能代表会话 JSON 大小或运行时内存占用。

2026-11-08 排查发现一个会话的 JSON 约 176.6MB，其中 4 份项目快照约 174.7MB；快照中的图片字符串出现 148 次、共约 169MB，只有 34 张不同图片、约 39MB。没有原生进程内存快照，尚不能认定为唯一 OOM 根因。

已改为复制普通对象时共享不可变图片字符串；连续等待中的同会话文件保存合并为最新状态，其他文件操作保持顺序。撤销历史和页面复制不再结构化克隆图片字符串。后台缩略图等待不可取消截图真正结束后才释放串行锁，并显式清空临时画布。

这些措施不删除撤回记录、隐藏图片或用户文件，不降低原图分辨率，也不改变会话 JSON 格式。现有大型会话在读取、解析、序列化和写入时仍可能产生较高峰值；完整快照的图片引用去重存储尚未实施，原生 Tauri 的实际项目 OOM 仍待复测。

`.crswap` 通常是 Chromium File System Access 写入使用的临时文件，崩溃或写入中断可能留下它；原生 Tauri 会话写入路径使用 `.tmp`。仅凭临时文件存在不能判定内存泄漏，排查时保留原文件及临时文件，不自动清理。

## AI 接入点可能受服务端 CORS 配置影响

**状态：待处理**

部分模型服务商或自建兼容接口的跨域资源共享（CORS）配置可能不允许 CoverFlow 所在来源发起浏览器请求，导致 AI 接入点无法正常调用。此时浏览器开发者工具中可能出现 CORS 错误，请求也可能在到达模型服务前被拦截。

排查时需确认服务端允许应用来源跨域访问，并允许请求使用的 HTTP 方法及请求头。该问题可能由服务端配置引起，不一定是接入点地址、密钥或模型配置错误。

## Tauri 模式暂不支持屏幕取色

**状态：待处理**

屏幕取色依赖浏览器 `EyeDropper` API，但 Tauri 使用的 WebView 不提供该 API，因此 Tauri 模式下的吸管按钮目前禁用。浏览器中是否可用取决于浏览器对该 API 的支持。

后续可评估原生取色能力，再决定是否恢复 Tauri 模式下的吸管按钮。考虑先改为应用内取色功能。
